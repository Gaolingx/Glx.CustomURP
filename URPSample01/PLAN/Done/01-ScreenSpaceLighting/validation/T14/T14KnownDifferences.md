# T14 known differences and limitations

> Updated 2026-11-16 after the SSR reflection denoiser port (02-SSRImprove T1–T5) and the SSR/SSGI
> HDRP alignment pass (03-SSRImprove2 T1–T3). Items below are deliberate URP adaptations or
> environment limits, not open bugs.

- URP has no per-material proxy volume: refraction uses the nearest box-projected reflection probe AABB, found through CullingResults.visibleReflectionProbes with a scene lookup fallback.
- Refraction samples the current opaque+sky color pyramid; HDRP's pre-refraction transparent ordering is not migrated, so transparents drawn after the opaque pass do not appear in refraction.
- SSGI runs its diffuse denoiser and consumes the denoised output; HDRP's raw SSGI return path is not reproduced (intentional, recorded since T6).
- SSGI and SSR sample HDRP's three blue-noise LUTs, packaged under `Resources/SsgiBlueNoise`; SSR binds the 1SPP tiles and SSGI the 8SPP tiles, matching HDRP's per-effect strata (the Owen 256 texture is shared). If the assets are stripped the kernels fall back to IGN + R2 and can keep a faint stipple at 1 spp. The SSR frame index is the raw `Time.frameCount` and the shader masks it to 256 frames, like HDRP's per-camera counter.
- Deferred consumes DepthNormals prepass material data, i.e. decal-deformed normals/decal color are not visible to SSGI/SSR tracing.
- Transparent SSR is Approximation-only and reprojects with hit-pixel and camera motion; URP 14 does not write transparent object motion, so moving transparent reflections can lag.
- SSR PBR uses the ported HDRP `ReflectionDenoiser` (TemporalAccumulationFullRes/HalfRes, CopyHistory, separable BilateralFilterH/V_FR/HR) instead of the former eighteen accumulation kernels. URP keeps `(radiance, weight)` in the history colour and the sample count in a separate `R16_SFloat` buffer rather than HDRP's `history.w`; reprojection is validated inline (far depth, off-screen, world radius) plus the screen-space extension `dot(N, historyN) < 0.75`.
- SSR has no object-motion stencil rejection and no exposure control: URP lacks the stencil bit, and the SSL stage runs before post exposure, so the reflection signal is pre-exposure and the exposure multipliers stay at 1.
- `ReflectionKernelMapping.png` is shipped with HDRP's `.meta` (sRGB, mipmaps, DXT1) and sampled by `(NoV, roughness)`: smooth reflections get almost no spatial radius and rough ones reach the full `denoiserRadius`. If the asset is stripped the kernel receives a white texture and falls back to a fixed full radius.
- Half resolution applies to PBR only (`fullResolution` off): trace, reprojection and denoising run at half the screen size, the history and sample counts follow that trace size, and the result is bilaterally upsampled with the SSGI `BilateralUpSampleColor`. Approximation keeps full-resolution 3×3 hole filling. Toggling reallocates PBR resources and resets the history. Half-resolution trace and denoiser map a trace pixel to the top-left full-resolution pixel of its 2×2 group (`2c`), matching HDRP's ray-traced reflection denoiser; HDRP's screen-space SSR has no half-resolution path to compare against.
- `singleReflectionBounce`, `affectSmoothSurfaces` and `denoiserRadius` are re-interpreted without a ray-tracing path: a single bounce only enables roughness-based radius scaling, `affectSmoothSurfaces` controls the >0.99 smoothness early-out, and `denoiserRadius` is the maximum kernel radius (halved at half resolution).
- The former SSR accumulation and speed rejection Volume parameters (`accumulationFactor`, `speedRejectionParam`, `speedRejectionScalerFactor`, `speedSmoothReject`, `speedSurfaceOnly`, `speedTargetOnly`, `enableWorldSpeedRejection`) and the `SsrAccumulationSpeed` debug view were removed after the reflection denoiser port; existing Volume overrides for them are ignored on load. `biasFactor` still biases the trace.
- GTAO and Screen Space Lighting own separate packed Hi-Z buffers; the duplicate depth-pyramid memory is accepted instead of a cross-feature broker.
- URP's Deferred compatibility path ignores MSAA, so the Deferred renderer does not promise MSAA support for these effects.
- URP 14.0.12 does not drive DynamicResolutionHandler: hardware dynamic resolution cannot rescale the RTHandle camera targets, so it is recorded as unsupported (static render scale is supported).
- APV is not integrated in URP 14.0.12, so probe-volume GI is marked unsupported; lightmap/SH/mixed lighting regresses green.
- SSGI miss fallback in Forward+ walks the per-pixel probe list from URP's reflection probe atlas and Forward+ zbin/tile cluster, with per-probe box weights and atlas LOD 0, and the sky ambient probe fills the remaining weight. Forward and Deferred keep the single default reflection cubemap because URP 14 only publishes the atlas/cluster globals in Forward+. Atlas-full probe drops are URP's own behaviour and can make the fallback colour jump.
- Reflection and preview cameras are rejected by `ScreenSpaceCapability` before any SSL pass runs, so SSGI/SSR are disabled rather than dimmed for probe rendering (HDRP disables SSGI for reflection cameras through FrameSettings as well).
- The plugin keeps the _SCREEN_SPACE_GI/_SCREEN_SPACE_SSR/_SCREEN_SPACE_TRANSPARENT_SSR/_SCREEN_SPACE_REFRACTION variants in every build because URP's prefiltering data only covers URP keywords. Plugin-level build stripping was evaluated but not introduced in T14: it changes release behaviour and needs its own correctness cycle.
- Metal, Android/OpenGLES, macOS/iOS and physical HMDs are not tested in this environment and are not claimed as supported.
- One 'CommandBuffer: temporary render texture not found (SetComputeTextureParam)' warning is logged on the first frame after the effects are enabled on DX11; it predates T14 (present in the T12 capture logs) and does not affect the measured images, which are identical to the recorded T12 hashes.
